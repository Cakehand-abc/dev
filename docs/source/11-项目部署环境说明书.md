# 项目部署环境说明书
版本 V1.1　2026年9月9日

## 1 部署架构概述与软硬件环境基准

智慧医养大数据决策分析系统采用现代前后端同源集成的 Spring Boot 可执行 Fat-JAR 交付形态，前端构建产物内嵌于后端静态资源目录中，支持单实例一键部署运行。底层依赖一套 MySQL 8.0 关系型数据库。软硬件部署基准配置如下：

| 系统组件维度 | 推荐生产运行基准 | 实训开发与测试验证基准 |
| --- | --- | --- |
| 操作系统 | Ubuntu 22.04 LTS / CentOS 7.9 / Windows Server | Windows 11 x86_64 企业级开发环境 |
| CPU 与内存 | 推荐 4 核 CPU 以上，8 GB 内存以上，配置高速 SSD | 4 核 CPU，16 GB 内存（实训开发机） |
| Java 运行时 | OpenJDK 17 LTS / Eclipse Temurin 17.0.12 | Java 17 生产兼容编译目标，通过 Maven 3.9 构建 |
| 关系型数据库 | MySQL 8.0.16 及以上（实测 8.0.46），utf8mb4 字符集 | MySQL 8.0.46，统一配置 Asia/Shanghai 本地时区 |
| 前端运行环境 | 无需独立 Node.js 服务（构建后静态资源内置于 JAR） | 编译期依赖 Node.js 22.12.0 及 Vite 7.3.6 构建工具 |
| 服务端口规划 | 应用主服务默认 8080 端口（可配置）；数据库 3306 端口 | 本地开发采用 8080，隔离测试验收采用 18081 与 13317 端口 |
| 终端浏览器 | Google Chrome 120+、Microsoft Edge 等现代浏览器 | Chrome 152 自动化测试环境全部通过 |

## 2 数据库初始化与升级规范

1. 全新数据库初始化：在 MySQL 8.0 实例中，首先使用具备 DBA 权限的账号执行 database/00-create-database.sql 建立 smart_care 数据库并赋予专用连接用户权限；随后执行 database/01-schema.sql 顺序初始化全部 18 张表结构、外键与联合索引。

2. 权限隔离原则：生产环境下应用数据库账号仅授予 SELECT、INSERT、UPDATE、DELETE 数据操作权限，禁止授予 DROP 等破坏性 DDL 权限，确保底层数据库安全。

3. 时区配置强一致：数据库服务器时区必须明确设置为 +08:00，JDBC 连接串必须明确声明 connectionTimeZone=Asia/Shanghai，杜绝跨时区导致的体检与定位时间漂移。

## 3 关键环境变量与核心配置字典

系统遵循 12-Factor 现代化云原生配置原则，核心配置支持通过系统环境变量解耦注入：

| 环境变量名称 | 默认值或配置示例 | 配置语义与安全加固说明 |
| --- | --- | --- |
| DB_URL | jdbc:mysql://127.0.0.1:3306/smart_care?useUnicode=true&characterEncoding=UTF-8&connectionTimeZone=Asia/Shanghai | 数据库 JDBC 连接串，必须显式声明编码与上海时区 |
| DB_USERNAME | smart_care_app | 应用连接专用数据库操作账号，生产严禁使用 root |
| DB_PASSWORD | 自定义强密码（交互式配置） | 数据库账号访问密码，严禁明文硬编码至配置文件 |
| APP_ADMIN_PASSWORD | 自定义管理员初始化密码 | 仅首次空库创建 admin 时生效，要求 12~72 字符，包含大小写与数字 |
| SERVER_PORT | 8080 | Spring Boot 应用监听端口，可按环境需要灵活重定向 |
| SPRING_PROFILES_ACTIVE | demo（演示）/ local（本地）/ prod（生产） | 运行 Profile 模式，demo 开放模拟入口，prod 强制安全加固 |
| APP_SEED_DEMO | true / false | 仅 demo 环境生效，首次启动时自动填充基础演示数据 |

## 4 系统一键构建与打包流程

项目根目录下提供了自动化打包脚本 scripts/build.ps1，在 PowerShell 中执行该脚本即可完成端到端自动化编译打包：

1. 脚本首先进入 frontend 目录执行 npm ci 与 npm run build，通过 Vite 7 编译生成优化压缩后的前端静态文件；

2. 将前端 dist 产物自动化复制至后端 src/main/resources/static 目录中；

3. 调用 Maven Wrapper（mvnw.cmd）执行标准构建打包，全量运行 28 项自动化测试；

4. 在 target 目录下生成开箱即用的可执行文件 dev-0.0.1-SNAPSHOT.jar，实现零依赖一键运行。

## 5 启动运行与常用 Profile 配置模式

1. 演示模式启动（面向实训结项答辩与现场演示）：

执行命令：.\scripts\start.ps1 -Profile demo -Port 8080。该模式会自动初始化内置示例老人、健康体检与围栏数据，并开放 SimulationPanel 轨迹模拟注入工具，方便现场交互演示。

2. 生产模式启动（面向机构正式部署）：

执行命令：java -Dspring.profiles.active=prod -jar target/dev-0.0.1-SNAPSHOT.jar。生产模式下自动屏蔽任何模拟注入端点，强制启用严格的 HTTPS Cookie 安全策略与敏感信息审计日志。

## 6 常见部署故障与应急排查手册

测试与运维团队总结了常见的部署环境故障与标准应对处置方案：

| 故障现象 | 常见根因分析 | 标准处置与排查步骤 |
| --- | --- | --- |
| 启动提示缺少 APP_ADMIN_PASSWORD | 首次初始化空库时未提供管理员初始密码 | 在环境变量中显式配置满足长度复杂度要求的 APP_ADMIN_PASSWORD 后重新启动 |
| Access denied for user 连接失败 | 数据库账号密码错误或未授予远程授权 | 核对 DB_USERNAME 与密码，检查 MySQL 用户主机白名单（如 % 或 localhost） |
| Web 端口 8080 Address already in use | 8080 端口已被本机其他后台服务占用 | 修改环境变量 SERVER_PORT=18080，使用备用端口启动应用 |
| JAR 文件重命名失败（Text file busy） | Windows 系统锁定了正在运行中的旧 JAR | 在任务管理器中正常终止原 Java 进程，再执行构建打包 |
| 设备定位接口返回 401 Unauthorized | 穿戴设备未在请求头携带合法 X-Device-Key | 在管理员腕表管理界面重新签发密钥，并将新密钥配置进硬件网关 |
| 历史健康图表时间显示异常 | 数据库时区与应用系统时区未对齐 | 检查 MySQL 数据库参数 time_zone，并在 DB_URL 中声明 Asia/Shanghai |
