# 测试计划
版本 V1.1　2026年9月9日

## 1 测试背景与总体质量目标

本项目为企业级框架技术开发实训核心成果，系统涉及多角色业务协同、海量高频时空数据处理与并发事务更新。为确保交付成果符合工业级软件工程标准与高校实训考评要求，特制定本测试计划。总体质量目标为：系统功能需求覆盖率 100%，核心业务测试用例通过率 100%，关键业务接口高并发压力测试错误率保持 0.00%，阻断性与严重性技术缺陷完全清零。

## 2 测试范围与技术类型

测试活动覆盖系统全生命周期，重点划分为六大核心测试类型：

| 测试类型 | 测试核心范围 | 重点关注技术指标与质量属性 |
| --- | --- | --- |
| 单元与集成测试 | 领域服务类（CareService, GeoService）、安全拦截器与 Mapper 映射器 | 代码逻辑覆盖率、业务边界异常分支与事务回滚一致性 |
| RESTful 接口冒烟 | 认证中心、老人档案、健康检测、医生随访、腕表管理等 16 项端点 | HTTP 状态码符合契约、JSON 结构完整性、字段脱敏规范 |
| 前端界面端端验收 | Vue 3 页面渲染、Element Plus 表单校验、GeoCanvas 画布自适应 | UI 响应性、控制台 0 报错、多分辨率排版兼容性 |
| 高并发性能压测 | 双十万级背景数据下对首页大盘、健康检测、设备分布发起压测 | 系统吞吐量（QPS）、平均响应时间、P95 延迟（< 2.0s）、错误率 |
| 安全性与权限测试 | 未认证访问、越权操作、CSRF 跨站请求伪造、弱口令防护 | Spring Security 过滤链防护有效性、Session 状态隔离机制 |

## 4 缺陷等级定义与全生命周期流转机制

系统缺陷统一纳入《03 系统测试日志》动态台账管理，划分为四级严重程度并实行严格闭环：

| 缺陷级别 | 影响范围与严重性定义 | 处置时限与归宿要求 |
| --- | --- | --- |
| Fatal（致命） | 系统无法启动、数据库死锁崩溃、核心认证彻底瘫痪 | 立即组织全员排查，阻断后续测试，4 小时内完成修复 |
| Critical（严重） | 越权修改数据、乐观锁失效导致脏写覆盖、围栏告警风暴 | 主责开发工程师当日攻坚闭环，并在测试日志中复盘记录 |
| Major（一般） | 图表统计口径微小偏差、非核心分页参数边界未约束 | 24 小时内完成代码修改并提交回归验证测试 |
| Minor（轻微） | 界面文字微小拼写错误、列表自适应局部微小样式偏差 | 在项目结项收尾阶段统一规范化美化并归档 |
